Share a script library you wrote

A script library gives other people's stacks new commands and functions. If you wrote one that others could use, it can be listed on the Libraries page, where people can read it and install it into OXT-Beyond.

What you need

  • Your library as a script-only stack: one text file whose name ends in .livecodescript and whose first line is script "your.library.name". Choose a name of your own, with no spaces, such as anna.easing.
  • Handler names that are yours alone. Start each with a short prefix, such as ezMove: two libraries cannot both have a handler called move.
  • A title, your name as you want it shown, and a sentence or two about what the library is for.
  • A licence: GPL 3, or one of the short licences that can be used together with it (MIT, BSD, Apache 2.0 or LGPL 3). Whichever you choose, a program built with OXT-Beyond holds its GPL 3 engine and is shared under GPL 3 as a whole.
  • If you can, a demo: a stack that uses your library, shared in the gallery like any other stack. People can then try your library in their browser before they install it.

What makes a library work here

  • Plain script only: no native code, no shell, no starting other programs.
  • Using the internet and files is fine. The library's page will say so.
  • If it handles messages that the engine sends, such as openStack or keyDown, pass them on (pass openStack). A library gets these from every stack.

How to send it

  1. On the forum. Attach the library file to a post on the OpenXTalk forum, with its title, your name, what it does and the licence you choose. We will do the rest.
  2. If you use GitHub: add a folder libraries/your-library-name/1.0/ with your library and a listing.json to the stacks repository, in a pull request. The repository's README shows how.

A person reads every library before it is listed, usually within a few days. Why a library is looked at more closely than a stack.
